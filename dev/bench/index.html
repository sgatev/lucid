Lucid benchmarks

How to read these
Each point
One commit on main, oldest on the left. Click a point to open that commit on GitHub.
The value
Nanoseconds one iteration of the benchmark took, so lower is better. The axis starts at zero, which is what keeps a change in the line proportional to the change in the work.
Throughput
Megabytes of source a second, and lines of it, beside the name of every benchmark that counts what it reads, and gathered at the top of the page for each stage of the pipeline and for the compiler as a whole. A line is one with anything other than whitespace on it, so the empty lines between functions are not counted. A time cannot be compared between two benchmarks that read different amounts, which is what a rate is for. Commits measured before lines were counted have megabytes alone.
Lucid against C++
The same program written in each language, run whole as a process of its own, so starting it and generating its input are in both times. The C++ is built with -c opt. Both lines share one chart, in milliseconds, and the ratio is of the newest commit.
Hovering
Shows the commit that was measured and its message, how many iterations the measurement averages over, and the throughput of that commit rather than of the newest one.
A jump with no change behind it
A run measures wall time on a shared machine, so a single point can move without the code having. What a benchmark says is in the trend across several commits rather than in one step.
The names
Grouped by the binary that declares them, because a name is only unique within one: three benchmarks are called Function.
